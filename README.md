# 공모전 온라인 심사평가 시스템 (AID사업단)

2026년도 지능형 업무 프로세스 자동화 공모전(P-AI Automation) 심사용 웹 시스템입니다.

> 자세한 사용 방법(관리자·심사위원)과 수정할 때 참고할 설계(데이터 구조, API, 판정 로직, 수정 가이드)는
> `AID_20261125_비교과_공모전온라인심사시스템설계서.md`를 보세요.
타 부서 심사 사이트(kbu.pjhpjh.kr)의 화면 구성을 참고하되, 우리 공모전 세부계획서 5.2~5.4, 6.4와 심사서류 [서식 1~5]에 맞춰 다시 만들었습니다.

## 1. 반영한 심사 방식

| 구분 | 내용 | 근거 |
| --- | --- | --- |
| 심사 구분 선택 | 기본값: 1차 심사(기획안 서면, 11. 26., 분야별 6팀 진출) / 2차 최종심사(발표·시연, 12. 9., 분야별 1·2·3등 수상). 관리자 화면 "설정"에서 이름·일자·평가 방식·작동 검증·결과 처리(진출/수상)·선발 수를 바꾸거나 추가·삭제·순서 변경 | 운영변경기록(11-16) |
| 심사위원 | 관리자 화면 "설정 > 심사위원 명단"에 등록하면 접속 화면에서 목록으로 선택(명단 외 접속 차단). 명단이 비어 있으면 성함 직접 입력 | 5.4 |
| 분야 선택 | 전체 / Lv1 아이디어 / Lv2 해커톤 / Lv3 PoC (접속 시 선택, 상단 탭으로 전환) | 3.1 공모 분야 |
| 분야별 배점 | 아이디어 30·30·20·20 / 해커톤 10·15·35·25·15 / PoC 15·15·25·30·15 | 5.2 심사 기준 |
| 1차·2차 항목명 | 1차는 "구현 계획의 실현가능성", 2차는 "실제 구현·작동성" | 5.2 ※ |
| 작동 검증 | 2차 해커톤·PoC만: 4개 항목 통과/미통과, 처리시간(전·후) 절감률 자동 계산, 결과 정확도 유지/저하 | 6.4, [서식 3] |
| 이해충돌 회피 | 접속 시 [서식 4] 확인, 출품작별 "회피" 제출, 회피 위원 제외 평균 | 5.4, [서식 4·5] |
| 진출 처리 | "다음 심사 진출" 구분은 분야별 평균 고득점순 N팀 "진출", 관리자 버튼으로 다음 심사 구분 대상 지정 | 6.1 |
| 수상 처리 | "수상" 구분은 평균 순 1·2·3등. 작동 검증을 켠 구분에서는 해커톤·PoC 검증 통과작만 진출·수상 | 5.3.4 |
| 동점자 처리 | 아이디어: 문제 정의 → 창의성 / 해커톤: 실제 구현·작동성 → 업무개선 효과 / PoC: 업무개선 효과 → 실제 구현·작동성 | 5.3.4 |

※ 작동 검증 "통과"는 해당 작품을 채점한 위원의 과반이 4개 항목 모두 통과로 판정한 경우로 계산합니다(계획서에 판정 방식이 없어 정한 기준. 바꾸려면 `server.js`의 `passed` 계산식 수정).
※ 같은 결과물이 2개 분야에서 수상권에 든 경우(점수 높은 분야에서만 수상)는 자동 처리하지 않으므로 결과 집계 화면에서 직접 확인합니다.

## 2. 구성

```
server.js            서버 (Node.js 18 이상, 외부 패키지 없음)
public/criteria.js   심사 기준(배점·항목·동점 처리) — 기준 변경은 이 파일만 고치면 됨
public/index.html    심사위원 화면  (/)
public/judge.js
public/admin.html    관리자 화면    (/admin)
public/admin.js
public/style.css
seed/entries.json    출품작 14건(11.25. 16:37 접수분, 중복 정리). 처음 실행할 때 자동 등록
data/db.json         실행 시 자동 생성 (출품작·제출 점수·로그), db.json.bak 직전본
```

## 3. 서버에 올리기 (Docker, 권장)

```bash
cp .env.example .env          # JUDGE_CODE, ADMIN_PASSWORD 필수 입력 / FORM_SYNC_URL, FORM_SYNC_KEY 선택
docker compose up -d --build
docker compose ps             # healthy 확인
```

- 이미지에는 프로그램만 들어가고, 출품작 목록(`seed/`)은 읽기 전용으로 연결되어 처음 1번 자동 등록, 점수는 볼륨 `judging-data`에 유지
- 포트는 `127.0.0.1:8080` → 서버의 리버스 프록시에서 HTTPS 연결
- 구글 폼 응답 연결(선택): `apps-script/FormSync.gs`를 응답 시트에 웹 앱으로 배포하고 URL·키를 `.env`에 입력. 연결이 안 되면 관리자 화면 "CSV 파일로 불러오기" 사용
- 자세한 절차·백업·복원은 설계서 11절

## 3-1. Docker 없이 실행

1. 서버에 Node.js 18 이상 설치 (`node -v`로 확인)
2. 이 폴더 전체를 서버로 복사 (`data` 폴더는 없어도 됨)
3. 실행 (접속 코드·비밀번호는 새로 정해서 사용)
   ```bash
   JUDGE_CODE='심사위원접속코드' ADMIN_PASSWORD='관리자비밀번호' PORT=8080 node server.js
   ```
   - 계속 켜 두려면: `npm i -g pm2` 후 `JUDGE_CODE=... ADMIN_PASSWORD=... pm2 start server.js --name contest-judging`
   - Windows 서버: PowerShell에서 `$env:JUDGE_CODE='...'; $env:ADMIN_PASSWORD='...'; node server.js`
4. 외부 공개 시 Nginx 등으로 HTTPS를 붙여 `http://127.0.0.1:8080`으로 프록시 (접속 코드가 평문으로 오가지 않도록 HTTPS 필수)
5. 백업: 관리자 화면 "전체 백업(JSON)" 또는 `data/db.json` 파일 복사

| 환경변수 | 설명 | 기본값 |
| --- | --- | --- |
| JUDGE_CODE | 심사위원 접속 코드 (필수) | - |
| ADMIN_PASSWORD | 관리자 비밀번호 (필수) | - |
| PORT / HOST | 포트 / 바인딩 주소 | 8080 / 0.0.0.0 |
| DATA_DIR | 데이터 저장 폴더 | ./data |

## 4. 운영 순서

1. 출품작은 서버를 처음 실행할 때 `seed/entries.json`에서 자동 등록됨(별도 작업 없음). 이후 접수분은 `/admin` → 출품작 관리 → "구글 폼에서 불러오기"(또는 CSV) → 미리보기 확인 → 반영
2. 설정 → 심사위원 명단 입력(접속 화면에서 목록으로 선택) → 심사 구분 확인·수정(이름, 일자, 진출 수 등)
3. 심사위원에게 주소와 접속 코드 안내 → 위원은 성함 선택·코드 입력, 심사 구분·분야 선택 후 채점
4. 심사 현황에서 제출 여부 확인. 위원이 수정을 요청하면 해당 칸 "취소" 후 다시 제출
5. 결과 집계 → 결과 확인 → "이 결과로 ○○ 진출팀 지정" → 출품작 관리에서 다음 심사 체크 확인
6. 마지막(수상) 심사 후 결과 집계 → CSV 내려받기 → [서식 5] 집계표·결과보고에 활용

## 5. 유의 사항

- 출품작 자료 링크에는 학번·연락처 등 개인정보가 담긴 파일이 연결되므로, 구글 드라이브 공유 범위를 심사위원 계정으로 한정합니다.
- 위원이 입력 중인 점수는 해당 브라우저에 임시 저장되며, "제출"해야 서버에 기록됩니다. 제출 후에는 위원이 직접 고칠 수 없습니다.
- 온라인 제출 점수와 별도로, 증빙용 서명 평가표([서식 1·2]), 이해충돌 확인서([서식 4])는 출력해 서명을 받습니다.
